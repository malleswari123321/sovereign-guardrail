Sovereign Multi-Cloud Data Boundary & Cross-Border Residency Guardrail

A Linux kernel filter that lets a server talk to approved cloud regions and silently drops traffic to everywhere else. Tested against live AWS S3 buckets in Mumbai and N. Virginia.

How it works

Companies and regulators often require that data stays inside certain regions. Firewalls usually enforce that in userspace, where an application can route around them. This guardrail runs inside the Linux kernel instead, so no application on the host can skip it.

  • A C program is attached to the egress hook of eth0 through Traffic Control (clsact).
  • For each outgoing packet it reads the destination IPv4 address and compares it with an allowlist of Mumbai S3 ranges.
  • A match returns TC_ACT_OK and the packet leaves. No match returns TC_ACT_SHOT, the packet is dropped, and a counter in a BPF map goes up.
  • A Go program loads the compiled object, attaches the hook, and prints the drop counter.

Proof it works

A timed-out connection alone could be a network fault. To rule that out, the kernel program counts its own drops, and the Go loader reads the counter while the test runs.

Limits and next steps

This is a proof of concept, and here is what it does not do.

  • IPv4 only, egress only, and one interface (eth0).
  • The allowlist is hardcoded. Cloud IP ranges change, so the next step is pulling AWS ip-ranges.json, filtering for ap-south-1, and refreshing an LPM_TRIE map on a timer.
  • No throughput or latency benchmarks yet, so I make no performance claims.

Tested on WSL2 (Ubuntu 22.04, kernel 5.15), Go 1.21.5, clang 14.
